# The Archive - 캐릭터 특징 자동 수집 및 저장 시스템

> `수많은 세계를 넘나들며 캐릭터의 특징과 개성을 수집하고 보존하는 디지털 아키비스트.  
> 아키비스트가 집필한 이 고대의 필사본은, 정체성들의 마지막 아카이브이자  
> 캐릭터의 본질과 원형(archetype)을 탐색하고, 기록하며, 연결하는 인격의 기록서입니다.`

---

## 📖 소개

**The Archive**는 사용자가 애니/게임 캐릭터의 이름 또는 특정 특징(예: '여우귀', '핑크색 머리')으로 검색하면, 인터넷에서 해당 정보를 자동 수집하고 요약하며, 사용자 검토(RUD)를 거쳐 Markdown 파일로 저장할 수 있는 도구입니다.

단순한 정보 수집을 넘어, **캐릭터의 본질과 서사**, 그리고 **개성의 맥락**까지 담아내는 **캐릭터 중심 데이터 아카이브**입니다.

---

## 🚀 주요 기능

### ✅ 현재 구현 예정 (1단계: MVP)
- **캐릭터 이름으로 정보 검색**
  - 나무위키, Wikipedia 등에서 자동 크롤링
  - 등장 작품, 성격, 외형, 기타 요소 정리

- **LLM 기반 요약 및 템플릿 정리**
  - GPT 또는 Claude API를 활용한 요약 기능
  - 항목별 Markdown 포맷으로 변환

- **사용자 검토 및 수정 (RUD)**
  - 요약된 정보에 대한 편집 UI 제공
  - 최종 수정을 반영한 파일 저장

- **Markdown / JSON 저장**
  - Obsidian 호환 `.md`로 저장 가능
  - 태그 및 연결 링크 자동 삽입

### 🔜 향후 구현 예정
- **특징 기반 검색** (2단계)
  - '핑크색 머리', '여우귀' 같은 특징으로 캐릭터 검색 가능
  - 키워드 기반 필터 및 태그 매칭 기능

- **태그 자동 생성** (3단계)
  - GPT 기반 태그 자동 생성기
  - 결과 파일에 태그 삽입 (`tags: [여우귀, 핑크색 머리]`)

- **Obsidian 호환 기능** (3단계)
  - 링크 구조 지원 (예: `[[카구야 신궁]]`)
  - 캐릭터 이미지 자동 수집 및 포함

## 📂 예시 저장 결과 (Markdown)

```markdown
# 카구야 신궁 (Kaguya Shinomiya)
---

## 기본 정보
- 출처: 카구야님은 고백받고 싶어
- 성별: 여자
- 소속: 슈치인 학원 학생회

## 성격
- 겉으로는 냉정하고 완벽주의자이나, 내면은 순수함
- 상대의 반응에 민감한 츤데레 기질

## 외형
- 긴 흑발, 붉은 눈
- 단정한 교복 차림

## 기타 특징
- 재벌가 출신
- 높은 두뇌 회전과 전략적 사고 능력

## 태그
- #여고생 #흑발 #츤데레 #엘리트 #카구야님
```

## 🏛️ 사용 예시

```bash
# 설치 (Gemini 요약을 쓸 때만 google-genai가 필요합니다)
pip install -r requirements.txt

# 규칙 기반: 나무위키 문장을 그대로 골라 노트를 만듭니다 (AI 없음, 무료)
python -m the_archive 설지 장리 --work 명조 --out archive

# Gemini 요약: 성격·외형·기타 특징을 한 문장씩 정리합니다 (API 키 설정은 아래 참고)
python -m the_archive "타카나시 호시노" --work 블루아카이브 --llm gemini

# 저장하지 않고 미리 보기, JSON도 함께 저장
python -m the_archive 파수인 --work 명조 --dry-run
python -m the_archive 파수인 --work 명조 --json
```

| 옵션 | 설명 |
| :-- | :-- |
| `--work`, `-w` | 작품: 블루 아카이브, 원신, 스타레일, 명조, 니케 (`블아`, `WW` 같은 줄임말도 됨) |
| `--out`, `-o` | 노트를 저장할 폴더 (예: Obsidian 볼트의 캐릭터 폴더) |
| `--llm gemini` | Gemini로 요약. 키가 없거나 실패하면 규칙 기반으로 진행 |
| `--model` | Gemini 모델 (기본: `GEMINI_MODEL` 값, 없으면 `gemini-flash-latest`). 쉼표로 여러 개를 적으면 앞에서부터 시도하고, 한도 초과(429)·과부하(503) 등으로 실패하면 다음 모델로 넘어갑니다. `-latest` 별칭이 실패하면 그 별칭이 가리키는 모델은 건너뜁니다 (별칭 정보는 `.cache/gemini_aliases.json`에 7일간 기억) |
| `--overwrite` | 같은 이름의 노트를 덮어쓰기 (기본은 건너뜀) |
| `--refresh` | `.cache/namu`의 캐시를 무시하고 다시 받기 |

### 🔑 Gemini API 키 설정

[Google AI Studio](https://aistudio.google.com/apikey)에서 키를 발급한 뒤, 둘 중 하나로 넣습니다.

1. **`.env` 파일 (이 저장소에서만 사용)**: `.env.example`을 `.env`로 복사하고 `GEMINI_API_KEY=` 뒤에 키를 적습니다.
   `.env`는 `.gitignore`에 있어 커밋되지 않습니다. 실행한 폴더의 `.env`를 먼저, 그다음 저장소 폴더의 `.env`를 읽습니다.
2. **사용자 환경 변수 (모든 프로그램에서 사용)**: Windows의 "계정의 환경 변수 편집"에서 `GEMINI_API_KEY`를 추가합니다.

둘 다 있으면 **환경 변수가 우선**합니다. 키를 코드나 노트에 직접 적지 마세요.

## 📚 출처

| 작품 | 출처 | 등급 | 비고 |
| :-- | :-- | :-- | :-- |
| 공통 | 나무위키 | 2차 | 기본 정보 표, 성격·외형·여담 |
| 명조 | 네이버 게임 **공식** 라운지 DB | **1차** | 게임사가 운영하는 공식 라운지의 공식 소개문 (〈유니버스 인류 기록〉) |
| 블루 아카이브 | 네이버 게임 라운지 DB | 2차 | 한국어 공식 소개문 (공식 라운지가 아니라 2차로 계산, 등록된 학생만) |
| 블루 아카이브 | Blue Archive Wiki (영문) | 2차 | 게임 내 공식 소개문(영문), 관계 |

- 네이버 라운지 DB는 자바스크립트로 그려지는 페이지라 **Playwright**로 설치된 Chrome을 띄워 읽습니다 (`pip install playwright`, 별도 브라우저 다운로드 없음). 로그인은 필요 없습니다.
- 수집 범위는 robots.txt가 허용하는 곳만 씁니다. 라운지 댓글(apis.naver.com)과 X(트위터)는 자동 수집이 금지되어 쓰지 않습니다.
- 노트의 각 줄에는 그 줄을 받치는 출처의 각주가 붙고, 핵심 출처는 Rules.md 기준(1차 → 많이 받치는 출처 → 날짜)으로 고릅니다.
- `--no-browser`: 라운지 DB를 건너뜀, `--no-extra`: 나무위키만 사용

## 📌 동작 방식

1. **수집**: `이름(작품 구분자)` 문서를 먼저 찾고, 없으면 `이름` 문서를 찾습니다. 받은 HTML은 `.cache/namu`에 저장해 같은 문서를 다시 요청하지 않습니다. 요청 사이에는 1초씩 쉽니다.
2. **파싱**: 프로필(성별·생일·소속 등), 원어 이름, 성우, 섹션(개요·여담 등), 최근 수정 날짜를 뽑습니다.
3. **정리**
   - 규칙 기반: 성격·외형 키워드가 들어간 문장을 **원문 그대로** 고릅니다.
   - Gemini: 출처에 있는 내용만 쓰도록 지시하고, 줄마다 원문 인용을 받습니다. **인용이 원문에 실제로 없으면 그 줄을 버립니다.**
4. **저장**: Obsidian 볼트 규칙에 맞춘 노트를 만듭니다.
   - 프론트메터(별칭, 태그, 출처, `Source_date`, 신뢰도), 기본 정보 표, 성격·외형·기타 특징
   - 줄마다 원문 인용이 붙은 **대조 체크리스트** (사람이 출처와 대조한 뒤 체크)
   - 신뢰도 계산 주석 (출처가 위키 하나이므로 대조 전에는 최대 40점)

> 노트는 초안입니다. 대조 체크리스트로 출처와 맞는지 확인한 뒤 쓰세요.
